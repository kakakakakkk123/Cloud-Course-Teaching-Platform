# 项目启动与初始化说明

## 1. 文档用途

这份文档用于帮助组内成员在 **数据库为空、前后端环境未配置** 的情况下，从零开始把项目跑起来。  
文档会重点说明：

- 需要准备哪些环境
- 后端和前端分别如何启动
- 数据库需要执行哪些 SQL
- 哪些 SQL 的执行顺序不能错
- 权限和菜单为什么容易出问题
- 出问题后优先查哪里

这份文档特别适合：

- 第一次在新电脑上跑这个项目
- 帮组员初始化环境
- 后续联调前做统一准备

## 2. 项目总体结构

当前项目分为两部分：

### 2.1 后端

- 目录：`ruoyi-admin`、`ruoyi-system`、`ruoyi-framework` 等 Maven 多模块工程
- 启动类：`ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`
- 默认端口：`8080`

### 2.2 前端

- 目录：`ruoyi-ui`
- 技术栈：Vue 2 + Element UI
- 开发启动命令：`npm run dev`
- 常见访问地址：
  - 本地开发：`http://localhost:81`
  - 后端接口代理：`/dev-api`

## 3. 启动前需要准备的环境

## 3.1 JDK

后端当前要求：

- **JDK 17**

依据：

- `pom.xml` 中 `java.version = 17`
- Spring Boot 版本为 `4.0.3`

注意：

- 如果使用 JDK 8 或 JDK 11，很容易出现编译失败
- IDEA 中项目 SDK、Maven Runner JDK、启动配置 JDK 都要确认是 JDK 17

## 3.2 Maven

建议：

- 使用本机 Maven
- 确保 Maven 使用的 JDK 也是 17

如果之前遇到阿里云仓库依赖下载失败，建议优先检查：

- `settings.xml` 镜像源
- 本地仓库缓存

## 3.3 Node.js 与 npm

前端当前基于 Vue CLI 4，建议环境：

- Node.js 16 左右更稳
- npm 可正常安装依赖

如果本机 Node 版本过高，通常也能跑，但若出现构建问题，建议优先换到较稳定的 LTS 版本。

## 3.4 MySQL

需要：

- MySQL 8.x

后端默认数据库配置在：

- `ruoyi-admin/src/main/resources/application-druid.yml`

默认配置是：

- 数据库地址：`localhost:3306/ruoyi`
- 用户名：`root`
- 密码：`123456`

如果你本机不是这套配置，需要修改：

- `application-druid.yml`

## 3.5 Redis

需要：

- Redis 服务启动

默认配置在：

- `ruoyi-admin/src/main/resources/application.yml`

默认值：

- 地址：`localhost`
- 端口：`6379`
- 数据库：`0`
- 密码：空

注意：

- 登录权限和菜单经常会被缓存到 Redis
- 如果改了菜单、角色权限后前端没生效，优先考虑清 Redis 登录缓存

## 4. 后端配置文件需要检查什么

## 4.1 数据库配置

检查文件：

- `ruoyi-admin/src/main/resources/application-druid.yml`

重点确认：

- MySQL 地址
- 数据库名
- 用户名密码

## 4.2 Redis 配置

检查文件：

- `ruoyi-admin/src/main/resources/application.yml`

重点确认：

- `spring.data.redis.host`
- `spring.data.redis.port`
- `spring.data.redis.password`

## 4.3 上传目录

在 `application.yml` 中有：

- `ruoyi.profile: D:/ruoyi/uploadPath`

如果本机没有这个目录，建议手动创建，或者改成自己电脑上的有效目录。

## 5. 首次启动前数据库初始化顺序

这是最重要的部分。  
如果数据库是空的，请按下面顺序执行 SQL。

## 5.1 基础库结构与系统数据

首先执行：

1. `sql/ry_20260417.sql`

作用：

- 初始化若依基础表
- 初始化系统菜单、角色、用户等基础数据
- 初始化项目当前主数据库结构的核心部分

如果你需要定时任务表，也可以执行：

2. `sql/quartz.sql`

说明：

- 如果项目当前没有用到 Quartz 功能，可以后补

## 5.2 学生档案与账户相关补充

继续执行：

3. `sql/20260522_create_edu_student_profile.sql`

作用：

- 创建学生学习档案相关表

4. `sql/20260523_academy_major_seed.sql`

作用：

- 初始化“教学组织 -> 学院 -> 专业”结构
- 注册页的学院和专业下拉框依赖它

注意：

- 如果不执行这份 SQL，注册页里学院字段会是空的

如果要补一些示例学生数据，可选执行：

5. `sql/20260522_student_number_demo.sql`

## 5.3 首页课程相关示例数据

如果希望首页、课程广场、课程详情能直接看到课程数据，执行：

6. `sql/20260526_homepage_demo_seed.sql`

作用：

- 初始化课程分类
- 初始化课程主数据
- 初始化课程内容
- 初始化课程注册关系
- 初始化点赞和轮播图示例数据

说明：

- 这份脚本是首页和课程演示的关键示例数据

## 5.4 教师菜单与课程权限补丁

如果教师登录后看不到“教学管理 / 课程管理”，执行：

7. `sql/20260528_teacher_course_menu_fix.sql`

作用：

- 补教学管理菜单
- 补课程管理菜单
- 补教师角色的课程、内容相关权限

注意：

- 执行后要重新登录教师账号
- Redis 里旧登录态可能会导致权限不立即刷新

## 5.5 考试模块表结构

如果要跑通教师侧考试模块，执行：

8. `sql/20260529_exam_module_schema.sql`

作用：

- 创建题库、试题、试卷、考试、考试记录、答题明细等表

## 5.6 教师考试菜单与权限补丁

如果教师登录后看不到“题库管理 / 成绩统计”，执行：

9. `sql/20260529_exam_menu_fix.sql`

作用：

- 补考试模块菜单
- 补教师角色的题库、试题、试卷、统计权限

## 5.7 其他可选 SQL

如果需要开放学生自主注册：

10. `sql/open_student_register.sql`

如果需要快速创建多类测试账号，可参考：

- `sql/create_three_accounts.sql`
- `sql/create_three_accounts_safe.sql`

## 6. 推荐的 SQL 执行顺序总结

如果是全新环境，推荐执行顺序如下：

1. `ry_20260417.sql`
2. `quartz.sql`（可选）
3. `20260522_create_edu_student_profile.sql`
4. `20260523_academy_major_seed.sql`
5. `20260522_student_number_demo.sql`（可选）
6. `20260526_homepage_demo_seed.sql`
7. `20260528_teacher_course_menu_fix.sql`
8. `20260529_exam_module_schema.sql`
9. `20260529_exam_menu_fix.sql`
10. `open_student_register.sql`（按需）

## 7. 前端如何启动

进入前端目录：

```bash
cd ruoyi-ui
```

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

启动后常见访问地址：

- `http://localhost:81`

说明：

- 这套前端通常通过代理将 `/dev-api` 转发到后端 `8080`

## 8. 后端如何启动

建议方式：

1. 用 IDEA 打开项目根目录 `RuoYi-Vue`
2. 确认 JDK 为 17
3. 等 Maven 依赖加载完成
4. 启动 `RuoYiApplication`

启动类位置：

- `ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`

默认端口：

- `8080`

## 9. 首次启动后的推荐检查顺序

启动前后建议按以下顺序检查：

### 9.1 先检查后端

确认：

- 后端能正常启动
- 控制台没有数据库连接错误
- Redis 连接正常

### 9.2 再检查前端

确认：

- `http://localhost:81` 能访问登录页

### 9.3 登录管理员

建议先用管理员账号验证：

- 是否能正常登录
- 左侧菜单是否完整

### 9.4 登录教师

建议再用教师账号验证：

- 是否有“教学管理”
- 是否有“课程管理”
- 是否有“题库管理”
- 是否有“成绩统计”

### 9.5 注册学生

检查：

- 注册页学院和专业是否有值
- 是否能成功注册

## 10. 权限问题为什么最容易出错

权限问题是这个项目初始化时最容易踩坑的地方，原因有 3 个：

1. 菜单来自数据库，不是前端自动生成
2. 角色和菜单的关系依赖 `sys_role_menu`
3. 登录后权限会缓存到 Redis 和前端 token 中

也就是说：

- 改完 SQL 不一定立刻生效
- 必须重新登录
- 有时还要清 Redis 登录缓存

## 11. 权限相关的典型问题与处理方式

### 11.1 教师看不到“教学管理 / 课程管理”

优先检查：

- 是否执行 `20260528_teacher_course_menu_fix.sql`

### 11.2 教师看不到“题库管理 / 成绩统计”

优先检查：

- 是否执行 `20260529_exam_menu_fix.sql`

### 11.3 菜单能看到，但点击提示“没有权限”

常见原因：

- 角色已分配菜单，但没有分配对应功能权限
- 修改了 SQL 后没有重新登录
- Redis 缓存里还保留旧权限

处理方式：

1. 先退出账号重新登录
2. 再强刷浏览器
3. 如仍无效，清 Redis 登录缓存

## 12. 课程管理最常见的初始化问题

### 12.1 课程分类接口 403

常见接口：

- `/dev-api/edu/category/tree`

原因：

- 教师角色缺少 `edu:category:list`

处理方式：

- 确认已执行 `20260528_teacher_course_menu_fix.sql`
- 若仍缺权限，补 `edu:category:list` 并重新登录

### 12.2 新增课程提示“授课教师不能为空”

原因：

- 后端或前端未正确带上当前教师 `teacherId`

当前状态：

- 这一问题已经在项目里修复

## 13. 注册页最常见的初始化问题

### 13.1 学院字段为空

原因：

- 没有执行 `20260523_academy_major_seed.sql`

处理方式：

- 执行该 SQL
- 刷新注册页

## 14. 首页最常见的初始化问题

### 14.1 推荐课程 / 最新课程为空

原因通常是：

- 没有执行 `20260526_homepage_demo_seed.sql`
- 或课程状态字段不满足首页查询条件

建议：

- 先导入这份示例 SQL 再看效果

## 15. 考试模块最常见的初始化问题

### 15.1 教师侧考试菜单不显示

原因：

- 没有执行考试菜单权限补丁 SQL

### 15.2 题库、试题、试卷、考试页请求 403

原因：

- 功能权限没有分配给教师角色
- 或旧登录态缓存未刷新

## 16. 建议准备的测试账号

建议至少准备：

- 管理员账号
- 教师账号
- 学生账号

作用分别是：

- 管理员：检查系统菜单和基础管理
- 教师：检查课程与考试主线
- 学生：检查注册、首页、学习入口

### 18.1 负责首页的同学

先确认：

- 首页能看到课程数据
- 搜索能跳转课程广场

### 18.2 负责教师模块的同学

先确认：

- 课程管理菜单可见
- 课程分类接口不 403
- 可新增课程和课程内容
- 可进入题库管理和考试链

### 18.3 负责学生模块的同学

- 学生能登录

- 课程详情能看到课程内容和考试内容

## 19. 总结

这个项目从空环境启动，最关键的不是代码本身，而是：

1. JDK 17
2. MySQL 和 Redis 配置正确
3. SQL 执行顺序正确
4. 菜单和权限补丁执行到位
5. 登录缓存和 Redis 缓存及时刷新

只要按本文档一步步做，基本就能把系统从空环境顺利跑通。
